# Implementation

status: implemented
updated: 2026-05-11

- Replaced the mixed provider picker model with explicit Entra and Auth0 workspaces. `providerRegistry.ts` owns provider route prefixes, menu groups, and switch targets; `useActiveProvider` drives the header selector from route state plus shared-tool localStorage state.
- Added provider-prefixed route trees under `/entra` and `/auth0` for the three existing flows, moved the flow implementations into shared `src/components/flows/` components, and changed the old unprefixed flow URLs into Entra redirects.
- Split persisted settings by provider with `app:settings:entra` and `app:settings:auth0`. Runtime-only secrets, tokens, assertions, and callbacks remain in memory and are cleared when the active provider route changes.
- Dropped Okta from provider ids, issuer allowlists, UI copy, README guidance, and active docs. Entra and Auth0 are now the only provider workspaces.
- Added the topbar provider selector and provider-aware sidebar menus. Shared tools remain outside provider route folders, and the JWT Decoder uses the active provider to choose Entra or Auth0/JWT claim references.
- Added Auth0-specific authorization request controls for RAR JSON and request modes. Auth0 URL mode includes `authorization_details`; PAR launches through `/api/oauth/auth0/par`; confidential-client JAR and PAR+JAR use `/api/oauth/auth0/request-object` when a runtime private key is available.
- Refined the Auth0 authorization code UI to match Auth0's request surface better: Auth0 now hides Entra-only `response_mode` handling, removes `select_account` from prompt choices, exposes Auth0-specific authorize parameters such as `connection`, `organization`, `screen_hint`, `max_age`, locale hints, `acr_values`, and `id_token_hint`, and appends them only to Auth0 authorization URLs.
- Kept the Auth0 authorize parameters in a single list while still hiding clearly dependent combinations such as `connection_scope` without `connection` and `invitation` without `organization`. Public-client request mode selection now normalizes stale unsupported JAR values back to valid URL/PAR options so the dropdown, description, and launch behavior stay aligned.
- Added provider-specific confidential token exchange routes under `/api/oauth/entra/...` and `/api/oauth/auth0/...`, sharing common handler logic while forcing the provider server-side.
- Retired the generic `/api/oauth/exchange-token` and `/api/oauth/client-credentials` routes. The shared handlers moved to `src/lib/oauthTokenHandlers.ts`, take the provider as a required argument, and ignore any `providerId` in the request body; the four provider routes are now thin wrappers over that module and the two generic URLs return 404.
- Stopped echoing Auth0 authorization-time extras back to the authorization code token exchange. Auth0 authorization code previews and server exchange requests no longer send `scope` or `audience` in the code-for-token step.
- Made the claim descriptions themselves provider-aware, not just the reference links. `StepDecode.claimDescriptions` is now split into `common` (25 standard JWT/OIDC claims), `entra` (23 Microsoft-specific claims, text unchanged), and `auth0` (`scope`, `permissions`, `gty`, `client_id`, `org_id`, `org_name`, plus an Auth0 wording for `azp`). `resolveClaimDescriptions` in `jwtClaims.ts` merges common with the active provider's overlay, and claim names under a URI namespace get a dedicated "custom namespaced claim" description instead of the unknown-claim fallback.
- Updated token decode and validation behavior for encrypted Auth0 JWE access tokens: decode shows the protected header and validation skips payload/signature checks with an explicit explanation.
- Tightened Auth0 follow-up behavior after review: access-token validation checks the configured audience, selected PAR/JAR launch modes stop with an inline error instead of falling back to a plain authorization URL, and Auth0 client credentials requires an audience in both UI validation and the server handler.
- Updated README and repository instructions for the new Entra/Auth0 workspace architecture, provider-scoped settings, and Auth0 RAR/PAR/JAR behavior.
- Gave `/entra` and `/auth0` real landing pages instead of two re-exports of the same generic page: each now names its workspace, explains how its settings differ, and links its flows from the provider registry plus the shared tools.
- Removed the unreachable provider picker inside the settings step. `showProviderSelector` was never passed, and `mergeProviderSettings` forces `providerId` from the storage namespace anyway, so the dropdown, its `setProviderId` prop, the three per-flow `handleProviderChange` handlers (~80 lines) and the orphaned `providerOptions`/`labels.provider`/`help.provider`/`placeholders.provider` strings are gone. Provider switching is route-driven only.
- Renamed the page metadata title from "Entra OAuth Playground" to "OAuth Playground" to match the multi-provider product.
- Moved the workspace switcher from the top-right of the topbar into the sidebar, directly under the logo and above the menu it controls, with a divider below it. The control is labelled by a `pi-id-card` icon rendered in both the selected value and the option rows rather than by a visible caption; the accessible name stays on a screen-reader-only label. The dropdown is now a shared `ProviderSelector` component rendered in both places; CSS decides which one is visible, so exactly one shows at a time: the sidebar copy for the static, drawer and reveal layouts above 992px, and the topbar copy for the slim, slim-plus and horizontal layouts and for every viewport below 992px, where the sidebar hides behind the menu button.
- Left-aligned the sidebar logo and title with the menu below. The vertical sidebar header was centred while the menu items sit at `2rem`; the header now uses the same left padding, and the slim sidebar keeps its centred logo explicitly instead of relying on the shared default.
- Refreshed the screenshots that do not require a real sign-in, captured at 1440px against the documented `https://localhost:3000` origin with demo identifiers: both workspace landings, overview, Entra and Auth0 settings, PKCE, Entra and Auth0 authorize, the JWT decoder with a synthetic token, and the claim-description dialog. `05-callback` through `10-call-api` still show the earlier single-provider UI and the README says so.
- Added Rich Authorization Requests validation in `src/lib/authorizationDetails.ts` (RFC 9396): the JSON must parse, be a non-empty array, contain only objects, give every entry a non-empty `type` string, and stay under 4096 characters once compacted. Invalid input is kept out of the authorization URL, shows an inline error on the field, and disables the launch button in both auth-code flows; the value sent is the normalized compact JSON rather than the raw textarea text. `/api/oauth/auth0/par` and `/api/oauth/auth0/request-object` enforce the same rules server-side and answer `invalid_authorization_details` with 400.
- Fixed the `authorization_details` placeholder in `en.json`/`de.json`: the JSON example contained unescaped ICU braces, so next-intl failed to parse the message and the example never rendered. Braces are now ICU-escaped.

- Entra PAR was implemented and then reverted. Measured against the live service, Microsoft Entra ID does not expose a pushed authorization request endpoint: `/{tenant}/oauth2/v2.0/par` returns a bare 404 for both a tenant GUID and `common` (while `/oauth2/v2.0/token` on the same tenant answers with a JSON AADSTS error), and the OIDC discovery document advertises no `pushed_authorization_request_endpoint`. PAR therefore remains Auth0-only. Revisit if Microsoft ships RFC 9126 support.
- Made "bring your own certificate" work in the client-authentication step. The SHA-1/SHA-256 thumbprints, `kid` and `x5t` were previously derived only inside the generate-a-self-signed-certificate path, so pasting a certificate issued elsewhere left the read-only thumbprint empty and the step validator blocked the flow — the realistic enterprise case for `private_key_jwt`. `computeCertificateThumbprints` in `certificate.ts` now derives them from the certificate's DER bytes whenever the field changes. Unit-tested against a certificate whose SHA-1 was verified independently with `openssl`.
- Added Playwright end-to-end tests (`pnpm e2e`, `e2e:offline`, `e2e:live`) in two projects. `offline` needs no credentials and covers the authorization request across every configuration: both auth-code routes for both providers with PKCE on and off, all prompt and response_mode values, the Auth0 parameter surface, the dependent-field disclosure rules, and RAR validation. `live` runs real round trips against configured tenants and skips itself by name when credentials are absent; settings are seeded straight into provider-scoped localStorage so each spec starts on the step it tests. Credentials live in a gitignored `.env.e2e.local`; `.env.e2e.example` documents every variable.
- Added the first interactive Entra round trip (`auth-code-entra.live.spec.ts`): a real sign-in against the tenant, then state verification on the callback, browser-side code redemption against Entra's SPA token endpoint, nonce round-trip into the ID token, and a Microsoft Graph `/me` call. Getting it green fixed three things in the shared sign-in driver, all of which also applied to Auth0. Microsoft's submit control is an `input[type=submit]` whose accessible name changes per step, so it is now targeted by its stable `#idSIButton9` id rather than by "Next"/"Sign in". The page rehydrates after first render and discards anything typed before that, which submitted an empty field and failed with "Enter a valid email address", so the driver now waits for the page to go quiet and confirms each value survived. Most importantly, waiting on the popup's `close` event was a race: the callback page closes itself about 100ms after posting the code, so the one-shot event had usually already fired and the wait burned its full 60s timeout — long enough for Entra to reject the code as expired. Polling `isClosed()` instead took the flow from 1.2 minutes to 13 seconds and was the whole cause of the `AADSTS70008` failure.
- Completed the Entra live matrix on top of that driver: confidential-client round trips with a client secret both with and without PKCE, confidential `private_key_jwt` through the interactive flow, `response_mode=form_post` (the only spec that reaches the `POST` branch of the callback route, asserting the code arrives in `callbackBody` and not in the callback URL), and streamlined mode reaching Validate with no further clicks. The no-PKCE public-client spec pins a provider behaviour that turned out to differ from the assumption: Entra recognises a Single-page application redirect URI and rejects the authorization request outright with `AADSTS9002325`, redirecting back with an error rather than issuing a code that could not be redeemed — so the assertion is on the callback error, not on the token response. `signInToEntra` now returns early when the popup has already left the sign-in pages, which is what that rejection looks like from the driver's side.
- Extended the same coverage to Auth0 and factored the shared wizard driving into `e2e/support/authCode.ts`, so both provider specs run one implementation and only the provider-specific assertions differ. Auth0 now has public-client round trips with and without PKCE, confidential-client round trips with a client secret both ways, and streamlined mode. The public no-PKCE spec records a genuine divergence between the providers: the configuration Entra refuses outright is accepted by Auth0, so both behaviours are pinned rather than assumed to match. The Auth0 public spec also asserts the code exchange omits `scope` and `audience`, which is deliberate app behaviour that was previously only described in this file.
- Added a `warmup` Playwright project that both other projects depend on. Next.js dev compiles routes on demand, so the first wave of parallel workers raced the compiler and timed out on navigation — failures that looked like broken specs but were only a cold server. Visiting every route once, sequentially, makes a full cold-start run deterministic.
- Added Vitest (`pnpm test`, `pnpm test:watch`) with 92 unit tests over the pure modules: provider route mapping and switch targets, the issuer allowlist and expected endpoint derivation, `issuerMatchesExpected` including the forged-issuer case from the review, the token endpoint SSRF refusals, RAR validation, JWT/JWE decoding, and provider-aware claim description resolution. Node environment only; components and routes are still exercised through the app.
